# The paraphrase bank

IELTS questions never reuse the passage's words. The question says *"a feeling of
unease"*, the passage says *"a sense of unease"*. Spotting that swap **is** the test,
and the same swaps come back book after book — so every pair met in a finished test is
worth keeping.

## Where things live

| | |
|---|---|
| `vocab/paraphrases.json` | the bank — `{"<test>": [pair, …]}`, one key per test, same shape as `vocab/learning.json` |
| `generated/paraphrase/paraphrase.html` | the practice page (generated — never hand-edit) |
| `dev/scripts/build_paraphrase.py` | builds that page; run by `build_index.py`, so a rebuild always refreshes it |
| `scripts/paraphrase.py` | harvest candidates, add pairs, report coverage |

A pair is

```json
{"q": "feeling of",  "p": "sense of",  "qno": "31",
 "qtext": "the whole question sentence",  "ptext": "the whole passage sentence",
 "uz": "optional Uzbek gloss"}
```

`q` = the **question's** wording, `p` = the **passage's** wording. `qtext`/`ptext` are
what the practice page highlights the phrase inside, so keep them — a pair with no
context is much weaker practice.

## Collecting a test

1. **Harvest the candidates.** Every test carries an `EXPL` table mapping each question
   to the passage evidence, so the raw material is already in the file:

   ```
   python3 .claude/skills/paraphrase-bank/scripts/paraphrase.py harvest reading/done/cambridge/cambridge-20/C20-r1.html
   ```

   It prints `qno · question wording · passage evidence`, one row per question. (It reads
   the C20/template family and the C21 JSON family; for an older hand-made test, read the
   questions and the passage directly instead.)

2. **Turn the rows into pairs.** This is the judgment part and it is yours, not the
   script's: for each row, name the *shortest phrase* on each side that carries the
   swap. Skip NOT GIVEN questions and any row where the question simply repeats the
   passage — a pair only earns its place if the wording actually changed.

3. **Add them.**

   ```
   python3 .claude/skills/paraphrase-bank/scripts/paraphrase.py add C20-r1 --file pairs.json
   ```

   (or pipe the JSON list on stdin). Duplicates on `(q, p)` are dropped, pairs are sorted
   by question number, and the page is rebuilt via `build_index.py`.

## Keeping it up to date

```
python3 .claude/skills/paraphrase-bank/scripts/paraphrase.py check   # coverage
python3 .claude/skills/paraphrase-bank/scripts/paraphrase.py list    # what's in the bank
```

`check` lists every **finished** test (anything under a `done/` folder) with its pair
count and names the ones still at zero. Two moments to run it:

- right after [move-to-done](../move-to-done/SKILL.md) files a test under `done/` — the
  test is fresh in the user's mind, so collect its pairs then;
- whenever the user asks about paraphrases, so nothing quietly falls behind.

If `check` reports finished tests with no pairs, say so and offer to collect them —
don't leave the gap unmentioned.

## The practice page

`generated/paraphrase/paraphrase.html` — reachable from the file browser and listed
under **Drills** on `dev/progress.html`. Three modes:

- **Flip cards** — one wording, recall the other; direction switchable
  (passage → question, question → passage, mixed). Space/→ reveals and advances.
- **Match** — five question wordings against five shuffled passage wordings, tap to pair.
- **Browse** — every pair with both sentences, the phrase highlighted in each.

Filter by test at the top. It is regenerated by `dev/scripts/build_index.py`, so adding
pairs is all it takes to update it.

## Notes

- The bank is per test, so a pair met twice in two tests is stored twice — that is on
  purpose: the repetition is the signal that it's a common swap.
- Words worth a full vocab card belong in a deck ([vocab-deck](../vocab-deck/SKILL.md));
  the bank is for *wording swaps*, which is a different thing from a new word.
- Committing follows the normal rule: only with the user's go-ahead, and never push.
