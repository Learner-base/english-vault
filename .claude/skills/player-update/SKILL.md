# Update the listening player

`/player.html` is a small page (~15 KB) that gathers **every listening track** in the project
into one playlist, for listening on the road. It has continuous autoplay, a seek bar, ±15s,
playback speed, resume-where-you-left-off, and lock-screen / car controls (Media Session API).
The audio itself lives once in `/audio/` (shared with the tests): Cambridge 20 tracks are local
`/audio/cambridge-20/…` files (marked "offline" — no duplicate copies); tests that reference a
remote URL (e.g. Cambridge 21/18) are marked "online" and need internet.

## When to run
Whenever the set of listening tracks changes:
- a listening test HTML is **added, deleted, renamed, or moved** under `listening/`
- a test's **audio source** changes (e.g. newly embedded audio, or a changed URL)

## How to update
The player is regenerated by `scripts/build_player.py`, which scans `listening/**/*.html`,
reads each test's `const AUDIO = […]` array (local `/audio/…` paths or a remote URL — or, for
older tests, embedded base64), and writes `/player.html`.

It is wired into the main page build, so the simplest path is:
```
python3 dev/scripts/build_index.py      # rebuilds index.html AND player.html
```
Or rebuild only the player:
```
python3 scripts/build_player.py
```

## Notes
- **This is already automatic** for anyone who follows the repo rule of running
  `dev/scripts/build_index.py` after adding/moving files — `build_index` calls `build_player` at the
  end. This skill is the manual/explicit path and the place that documents the player.
- Tracks are grouped by book and ordered by book → test → part. Labels come from the filename
  (`Cambridge <book>`, `Test <n>`, and `Part <k>` for the four-section Cambridge 20 tests).
- The player stays small because the audio lives once in `/audio/` and is referenced by path.
  To add offline audio for a book that currently streams from a URL (e.g. Cambridge 21),
  generate those tests with the `listening-generate` skill (it copies the tracks into
  `/audio/cambridge-<n>/`) and re-run the build; the player picks them up as offline automatically.
- `dev/player.html` is intentionally excluded from the `dev/index.html` file browser (it is an app page,
  like `dev/index.html`/`dev/progress.html`); reach it directly at `/player.html`.
